# Астро-часы на телефоне

Flutter-приложение: то же, что показывают [часы на ESP32-C3](../AstroClock),
плюс толкования из корпуса и разбор дня, которых на 240 пикселях не помещалось.

Карта считается на устройстве. Сеть нужна только текстам, и её отсутствие
убирает часть толкований, а не ломает экран.

## Что внутри

Четыре вкладки.

- **Карта** — биwheel: зодиак снаружи, транзитные планеты на своём кольце,
  натальные приглушённые, линии аспектов между ними. Асцендент прибит к левому
  краю, долгота растёт против часовой стрелки, поэтому метка Солнца на ободе
  работает суточной стрелкой. Второй режим — «небо», то же без натального слоя.
  Тап по глифу открывает его транзиты и толкования
- **День** — лунные сутки с названием и сферами, планетарный час, фаза и знак
  Луны, Луна без курса со временем выхода из знака, три самых точных транзита
- **Транзиты** — весь список с орбисами и признаком схождения, каждая строка
  разворачивается в толкование
- **Настройки** — натальные данные, место наблюдения, тема, адрес бэкенда,
  режим «только офлайн», счётчик локально сохранённых текстов

Тема по умолчанию живая: hue фона и текста берётся от управителя дня, hue
акцента — от управителя планетарного часа, знаки и планеты красятся собственной
эклиптической долготой. Это порт [packages/astro-palette](../packages/astro-palette),
он же лежит в прошивке часов. Восемь фиксированных тем оттуда же.

## Устройство кода

```
lib/core/ephemeris/    порт AstroClock/src/*.h на Dart
  ephemeris.dart       Солнце и Луна (Meeus), планеты (Standish), дома по Плацидусу
  transits.dart        натальная карта, поиск транзитов, Луна без курса
  lunar.dart           лунные сутки, таблица тридцати дней
  palette.dart         живая палитра, планетарные часы
  names.dart           русские имена и Unicode-глифы
lib/core/sky.dart      снимок неба; медленная часть считается в изоляте
lib/data/              настройки, HTTP-клиент, слой толкований
lib/features/          экраны
tool/                  сверка порта с прошивкой и со swisseph
```

Снимок неба разделён надвое нарочно. Положения, транзиты и палитра считаются за
единицы миллисекунд и живут в UI-потоке. Лунные сутки и Луна без курса стоят на
порядки дороже: первое ищет до тридцати восходов Луны, второе сканирует трое
суток с шагом полчаса. Их считает изолят, и результат возвращается примитивами.

## Толкования и офлайн

Источник толкований — интерфейс, а не конкретный класс. Реализаций три:

1. **правило** — текст собирается из таблиц приложения. Есть всегда, на любой
   ключ, сети не требует. Лунные сутки закрыты им полностью
2. **корпус** — тексты авторов из ZET. Сейчас лежат на бэкенде, ходим по
   `/api/corpus/*`
3. **кэш** — sqlite на устройстве. Всё, что приехало из корпуса, оседает здесь
   и дальше читается без сети

`CompositeInterpretationSource` опрашивает их по порядку и склеивает, а
переключатель «только офлайн» просто выкидывает из очереди тех, кому нужна сеть.
Источник каждого текста подписан в интерфейсе: читатель должен видеть, книга это
или шаблон приложения.

### Что нужно, чтобы рекомендации работали офлайн целиком

Разложено по слоям, от дешёвого к дорогому.

**Факты** (эфемериды, транзиты, дома, лунные сутки, планетарные часы, Луна без
курса) уже считаются локально. Здесь делать нечего.

**Корпус** — статические тексты, никакой модели для них не нужно.
`zet/corpus.jsonl` это 64 МБ; в sqlite с индексами по разобранным полям получится
того же порядка. Схема таблицы в
[cache_store.dart](lib/data/interpretation/cache_store.dart) специально совпадает
с тем, какой она была бы у предзалитой базы: заполнение меняется, вызывающий код
нет. Класть либо в assets, либо докачивать при первом запуске — второе честнее
по отношению к размеру установки.

**Скоринг v2** (`backend/src/optimal-timing/v2/predicates` и `pipeline`) —
детерминированный TypeScript без единого обращения к модели, около семисот строк.
Портируется на Dart тем же способом, что и эфемериды, и сверяется тем же
способом: гоняем оба на одной сетке дат и сравниваем. Пять канонических рецептов
это JSON, они кладутся в assets. После этого «подбери день под задачу» из
готового набора работает без сети.

**Свободный интент и нарративы** — единственное, что действительно упирается
в языковую модель: произвольный текст запроса превращается в рецепт, дни
получают человеческие описания. Варианты по убыванию разумности:

- заранее сгенерировать нарративы на две-три недели вперёд, пока сеть есть,
  и сложить в тот же кэш. Покрывает обычный сценарий целиком
- оставить онлайн и честно показывать, что этот кусок недоступен
- модель на устройстве (gemma-3n, qwen 0.6–4B через llama.cpp). Полтора-четыре
  гигабайта, и на таких размерах русский текст выходит бледный. Имеет смысл
  скорее как перефразирование готовых кусков корпуса, чем как рассуждение

То есть офлайн упирается не в «как запустить модель на телефоне», а в две
понятные инженерные задачи: перевезти корпус в sqlite и портировать скоринг.
Модель нужна только последнему слою, и его можно предвычислять.

## Точность

Порт сверяется двумя способами.

```bash
flutter test
```

Эталоны в [test/ephemeris_test.dart](test/ephemeris_test.dart) сняты с прошивки.
Ловит регрессию без pyswisseph и без сборки C++.

```bash
python3 tool/compare_port.py 250 138.7 2435108.5
```

Полная сверка: собирает [AstroClock/test/grid_dump.cpp](../AstroClock/test/grid_dump.cpp),
гоняет `tool/dump_grid.dart` на той же сетке и сравнивает обоих со swisseph.
Нужен `pyswisseph`, файлы эфемерид не нужны (флаг `MOSEPH` считает аналитически).

Замерено на 250 точках с 1955 по 2050 год:

| проверка | результат |
|---|---|
| Dart против прошивки | 0.000000° по всем величинам |
| Солнце против swisseph | 0.008° |
| Луна | 0.014° |
| Юпитер, Сатурн | 0.15–0.17° |
| остальные планеты | до 0.053° |
| асцендент, МС, куспиды | 0.73″ |

Худшие тела упираются в предел метода Standish: взаимные возмущения в него не
входят. Остаток по асценденту — это четырёхчленная нутация из `ephemeris.h`.

## Сборка

```bash
flutter pub get
flutter build apk --release
```

Собранный релизный APK лежит в `dist/` (51 МБ, arm64-v8a, armeabi-v7a, x86_64,
compileSdk 36). Ставится на телефон по USB:

```bash
adb install -r dist/astro-clock-release.apk
```

### Что пришлось подкрутить в android/

Шаблон Flutter 3.44 генерирует AGP 9.0.1 с Gradle 9.1, и на нём сборка падает
ещё на конфигурации: `shared_preferences_android`, `sqflite_android` и
`path_provider_android` объявляют себя способом, который AGP 9 уже не
принимает («'kotlin-android' plugin requires one of the Android Gradle
plugins»). В [settings.gradle.kts](android/settings.gradle.kts) стоит AGP
8.10.1 и Kotlin 2.1.0, в обёртке Gradle 8.12. Поднимать обратно можно, когда
плагины переедут.

В [gradle.properties](android/gradle.properties) выключен параллелизм. Иначе
скачивание с `repo.maven.apache.org` рвётся на рукопожатии: тот же файл и
`curl`, и голая Java по одному берут без единой ошибки, разваливаются именно
десятки одновременных соединений Gradle.

### iOS

Не собирался: на машине нет Xcode, а свободного места под него (около 40 ГБ
установленного плюс столько же на распаковку `.xip`) нет. Когда появится:

```bash
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -runFirstLaunch
brew install cocoapods
```

Без CocoaPods плагины sqflite, shared_preferences и path_provider не соберутся.

`flutter analyze` и `flutter test` работают без всякого из этого.

## Натальные данные

По умолчанию те же, что в [platformio.ini](../AstroClock/platformio.ini) часов.
Смещение от UTC вводится то, которое действовало в месте и в момент рождения,
с декретным и летним временем: для Москвы сентября 1984 это UTC+4, а не UTC+3,
летнее время отменили только 30 сентября.
