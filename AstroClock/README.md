# AstroClock

Часы на ESP32-C3 с круглым дисплеем GC9A01 240×240. Показывают транзиты текущего
неба к натальной карте владельца.

Эфемериды считаются на самом устройстве, сервер и WiFi для расчёта не нужны.
Раньше прошивка ходила за JSON на `/api/v1/ephemeris/planets` и без сети
показывала `HTTP 500`.

## Что на экране

Три режима, короткое нажатие кнопки (GPIO9) переключает по кругу:

- **биwheel** — зодиак снаружи, транзитные планеты на радиусе 79, натальные
  приглушённые на радиусе 56, линии аспектов между ними. Чем точнее аспект, тем
  ярче линия. Участники аспектов обведены кружком, ретроградные помечены точкой
  снизу. Между натальным и транзитным кольцами — засечки двенадцати куспидов
- **небо** — то же без натального слоя
- **список** — пять самых точных транзитов текстом, с орбисом и признаком
  схождения

Долгое нажатие (больше 0.8 с) переключает цветовую тему. Режим и тема переживают
перезагрузку через NVS.

Асцендент прибит к левому краю, долгота растёт против часовой стрелки. Отсюда
метка Солнца на ободе работает суточной стрелкой: вверху около полудня, справа
на закате, внизу в полночь, слева на восходе.

Луна без курса обводится двойным кольцом. Раньше она мигала, но мигание
перерисовывало весь кадр дважды в секунду и мешало разглядеть карту.

Соединения рисуются не хордой, а радиальной перемычкой между натальным и
транзитным кольцами: у соединения углы обеих точек почти совпадают, и хорда
на радиусе 45 вырождается в точку. Остальные аспекты остаются хордами.

Знаки зодиака — растровые глифы 13×13 из [src/glyphs.h](src/glyphs.h), 312 байт.
Параметрическая отрисовка дугами на этом размере читалась плохо.

## Дома

Куспиды по Плацидусу, все двенадцать, считаются на устройстве в
`ephem::houseCusps`. Плацидус делит не дугу, а время: промежуточный куспид это
точка эклиптики, прошедшая треть или две трети своего полусуточного пути от
горизонта к меридиану. Полусуточная дуга зависит от склонения точки, склонение
от её прямого восхождения, а восхождение как раз и ищется, отсюда итерация.

Сверено со swisseph (`swe.houses`, система `P`): в рабочих широтах расхождение
не превышает 0.1″, на 300 случайных моментов и мест при |широте| < 66° худшее
5.6″, у самых полярных кругов 11″. Пиксель экрана на радиусе колец это 0.76°,
так что разница невидима.

Аспекты к куспидам не ищутся: двенадцать дополнительных точек забили бы список
транзитов. Первый и десятый куспиды это и есть асцендент с серединой неба, они
же участвуют в аспектах как углы карты.

Угловые куспиды рисуются длинной засечкой, остальные восемь короткой и тусклой.

## Цвета

Тема 0 — живая палитра, порт [packages/astro-palette](../packages/astro-palette)
в [src/palette.h](src/palette.h). Темы 1–8 остались фиксированными, длинное
нажатие кнопки переключает по кругу все девять.

Схема библиотеки: hue фона, текста и рамки берётся от управителя дня, hue
акцента — от управителя планетарного часа. Источник hue геоцентрический, то
есть это прямо эклиптическая долгота планеты. Аспекты между семью классическими
планетами подмешивают насыщенность (гармоничные) и контраст фона (напряжённые),
с теми же весами и потолками, что в библиотеке.

По той же конвенции красится всё позиционное: знак зодиака берёт hue середины
своего сектора, планета — того градуса, где стоит. Кольцо зодиака от этого
становится плавным цветовым кругом. Цвета аспектных линий остались смысловыми
(гармоничные синие, напряжённые красные): hue от долготы стёр бы это различие.

Порт сверен с библиотекой на один и тот же момент: управитель дня, управитель
часа и номер часа совпадают, hue расходится на 0.004° (у библиотеки своя модель
Солнца), модуляция на 0.0013 по хроме. Конверсия OKLCH→RGB565 совпадает с
эталонной реализацией побитово по всем шести ролям.

Отличий от библиотеки два. Восход и закат считаются от настоящего Солнца из
`ephemeris.h`, а не приближением Спенсера: расхождение около минуты и заметно
только у самой границы планетарного часа. И модуляция от аспектов включена
всегда, тогда как в библиотеке `applyAspects` по умолчанию выключен.

## Сборка

Натальные данные задаются флагами в `secrets.ini`. Репозиторий публичный,
поэтому в [platformio.ini](platformio.ini) их нет: он подхватывает файл через
`extra_configs` и подставляет секцию `[personal]` в `build_flags`.

```
cp secrets.ini.example secrets.ini
```

```ini
[personal]
build_flags =
    -D NATAL_YEAR=2000
    -D NATAL_MONTH=1
    -D NATAL_DAY=1
    -D NATAL_HOUR=12
    -D NATAL_MINUTE=0
    -D NATAL_UTC_OFFSET=0.0   ; смещение от UTC на момент рождения
    -D NATAL_LAT=0.0
    -D NATAL_LON=0.0
```

`NATAL_UTC_OFFSET` — именно то смещение, которое действовало в месте и в момент
рождения, с декретным и летним временем. Для Москвы сентября 1984 это UTC+4, а
не UTC+3: летнее время отменили только 30 сентября.

Без `secrets.ini` сборка проходит на запасных значениях из
[src/config.h](src/config.h): эпоха J2000 в Гринвиче. Прошивка пойдёт, но
покажет заведомо чужую карту.

### WiFi

Только ради NTP и только через переменные окружения:

```bash
export ASTRO_WIFI_SSID='...'
export ASTRO_WIFI_PASS='...'
pio run -t upload
```

Без `ASTRO_WIFI_SSID` макрос не определяется, `ASTRO_USE_WIFI` не включается, и
стек WiFi в образ не линкуется совсем: 29.6% флеша против 69.9% с ним и с OTA.
Тогда время идёт от момента сборки или от последнего сохранения в NVS (см.
ниже), а во втулке времени вообще нет — его убрали ради живой карты.

Пароль в исходники не кладём: прошлый лежал прямо в `main.cpp` и уехал в
публичный репозиторий вместе с ним.

### OTA

Заливка по воздуху вместо USB — на время разработки удобнее, платится флешом и
тем, что радио висит включённым весь аптайм, а не пару секунд ради NTP:

```bash
export ASTRO_WIFI_SSID='...'
export ASTRO_WIFI_PASS='...'
export ASTRO_OTA=1
pio run -e ota -t upload
```

Без `ASTRO_OTA` собирается обычная USB-сборка даже из окружения `ota` — флаг
отдельный от WiFi нарочно, чтобы NTP можно было включить не платя постоянным
радио. Устройство отвечает на `astroclock.local` (mDNS), IP на секунду
показывается на экране после подключения — сверяться с роутером не нужно.

Партиционная таблица по умолчанию (`default.csv` из Arduino-ESP32) уже
двухслотовая, `app0`/`app1` по 1.25 МБ каждый — под OTA ничего менять не
пришлось, полный образ с WiFi укладывается в один слот с запасом.

Пароль опционален, `ASTRO_OTA_PASS`. PlatformIO не умеет подставлять его в
`upload_flags` статически из `platformio.ini`, поэтому на заливку:

```bash
PLATFORMIO_UPLOAD_FLAGS="--auth=$ASTRO_OTA_PASS" pio run -e ota -t upload
```

Задумано как временное решение на время разработки: одна переменная окружения
выключает — обычная USB-сборка перестаёт тащить WiFi и ArduinoOTA, ничего в
коде трогать не нужно.

## Точность

Планеты считаются методом Standish (JPL, кеплеровы элементы с вековыми
скоростями, полная трёхмерная задача), Солнце и Луна — рядами Meeus. Замерено
против swisseph на сетке 1955–2050 с шагом 37 суток:

| тело | макс. \|Δ\| | | тело | макс. \|Δ\| |
|---|---|---|---|---|
| Солнце | 0.008° | | Юпитер | 0.171° |
| Луна | 0.015° | | Сатурн | 0.178° |
| Меркурий | 0.017° | | Уран | 0.038° |
| Венера | 0.029° | | Нептун | 0.022° |
| Марс | 0.054° | | Плутон | 0.022° |

Асцендент и МС сходятся со swisseph до 0.1″.

Худшие тела, Юпитер и Сатурн, упираются в предел метода: взаимные возмущения в
него не входят. При транзитном орбисе 1–2° это 9–18% окна. Подгонка остатка
полиномом пробовалась и отброшена — на всём рабочем диапазоне остаток
периодический, а не вековой, и на двадцатилетнем окне подгонка ломала карты
восьмидесятых.

Для сравнения, усечённые ряды из `astro-palette` дают по Марсу 1.22°, по Луне
0.24°.

## Проверка

```bash
python3 test/compare_with_swisseph.py
```

Собирает `test/host_check.cpp` с теми же `ephemeris.h` и `transits.h`, что уходят
в образ, и сверяет со swisseph натальную карту, текущее небо, асцендент, МС,
ретроградность и орбисы найденных транзитов. Нужен `pyswisseph`; файлы эфемерид
не нужны, флаг `MOSEPH` считает аналитически.
