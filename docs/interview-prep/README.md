## Питч на 90 секунд (выучить дословно каркас)

> Я строил подсистему оптимального тайминга в продукте, который подбирает удачные
> временные окна под задачу пользователя. Первая версия классифицировала запрос по
> ключевым словам в одну из 9 категорий и считала день взвешенной суммой. Две дыры:
> всё, что вне 9 категорий, молча сваливалось в дефолт, и не было жёстких
> дисквалификаторов — плохой день мог набрать высокий балл из-за одного сильного плюса.
>
> Я переделал ядро на паттерн «LLM как компилятор». Свободный текст пользователя модель
> переводит в **Recipe** — структурный объект в закрытом DSL: список дисквалификаторов и
> взвешенных условий. Словарь предикатов закрытый (14 штук, фиксированные enum'ы планет и
> знаков), всё валидируется Zod-схемой. Модель свободна в *композиции*, но не может
> выдумать ни оператор, ни сущность. Дальше скоринг полностью детерминированный: LLM
> только на краях, ядро воспроизводимо и покрыто тестами.
>
> Главное, чем горжусь: с первого дня встроены eval-харнесс на gold-наборе и трейс на
> каждый запрос. Мы не катим изменения LLM, которые не можем измерить. Это и отличает
> «прикрутил API» от инженерии вокруг модели.

Дальше — пауза, дать задать вопрос. Глубину держит файл 02.

## Цифры и факты, которые надо помнить (конкретика убеждает)

| Что | Значение |
|---|---|
| Провайдер / модель | NVIDIA NIM, `nvidia/llama-3.3-nemotron-super-49b-v1.5`, OpenAI-совместимый API |
| Размер DSL | 14 предикатов, закрытые enum'ы (10 планет, 12 знаков, 5 аспектов, 8 фаз) |
| Few-shot | 5 канонических recipe из реального источника (Stellium electional cookbook), один источник правды в JSON |
| Валидация | Zod discriminated union, `tryParseRecipe` → null на провале |
| Ретраи | до 2 попыток, на провале схемы — фидбек ошибки обратно в модель |
| Скоринг | две стадии: дисквалификаторы (hard no) → взвешенные условия (градиент) |
| Семплинг | `temperature 0.2`, `top_p 0.95`, `max_tokens 2048` |
| Кэш | in-memory LRU, ключ `lang|нормализованный intent`, размер 100 |
| Eval | gold-набор, метрика recall по `must_*`, gate на PR, кэш байпасится |
| Трейс | на каждый запрос: промпт, модель, версия промпта, latency, cost, разбор по дням |
| Версионируется | schema_version, prompt_template_version, predicate/scoring_engine_version |
| Стратегия выката | v2 рядом с v1 (strangler), v1 уходит после паритета в eval |

> ⚠️ **Вставь реальные цифры команды и прода**, которых я не знаю: размер команды и кто
> что делал, объём трафика / число пользователей, реальные latency p95 и cost на запрос,
> что измерил до/после. Места помечены `[ВСТАВЬ: ...]` в файле 01.

## Три вещи не переврать (честность ловят на глубине)

- **Фидбек-луп спроектирован, но не построен.** Есть `feedback/README.md` со схемой
  каналов, кода нет. Не говори «система самообучается». Говори «заложил контракт под
  сбор размеченных данных, обучение — следующий шаг».
- **Eval — это recipe-correctness, не outcome-correctness.** Проверяем, что recipe
  содержит нужные предикаты, а не что рекомендованный день реально сработал. 5 gold-кейсов
  это сигнал, не покрытие.
- **README модуля устарел** (написано «scaffolding only»), по факту собрано: генерация
  recipe, контроллер `find-with-intent`, eval, трейс, vibes/narratives, фронт. Если
  откроют README при тебе — сам назови это до того, как заметят.
