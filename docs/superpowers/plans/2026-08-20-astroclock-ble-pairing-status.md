# BLE-пейринг AstroClock ↔ Flutter — статус (этап 1)

Записка для продолжения после того, как часы окажутся физически под рукой.
Код и коммит уже есть, ручная проверка на живом железе — нет.

## Что сделано и закоммичено

Коммит `ba17c92` в `feat/deploy-amsterdam`. Реализован этап 1 из более
крупной задачи (конфигурация часов из приложения): BLE-канал связи телефон↔
часы, пейринг, включение/выключение WiFi на часах с телефона.

Протокол — [AstroClock/docs/ble-protocol.md](../../../AstroClock/docs/ble-protocol.md).

**Прошивка**: [AstroClock/src/ble.h](../../../AstroClock/src/ble.h) (NimBLE
GATT-сервер, bonding + passkey display), [AstroClock/src/wifi_task.h](../../../AstroClock/src/wifi_task.h)
(неблокирующий автомат WiFi/NTP взамен старой блокирующей `syncTime()`),
интеграция в `main.cpp`, `h2zero/NimBLE-Arduino` в `platformio.ini`.

**Mobile**: `mobile/lib/state/device_controller.dart` (BLE-клиент на
`flutter_blue_plus`), секция «Часы AstroClock» + шторка пейринга в
`mobile/lib/features/device/`, поля сопряжённого устройства в `Settings`,
permissions в `AndroidManifest.xml`.

Натальные карты и конфигурация быстрого доступа на часах — сознательно не
входят в этот этап, следующие итерации.

## Что проверено автоматически

- `pio run` для трёх сценариев — все успешно, флеш укладывается:
  без WiFi 63.3%, WiFi+BLE 88.5% (~227 КБ своб.), WiFi+OTA+BLE 90.8%
  (~181 КБ своб.). NimBLE с Secure Connections добавил ≈460 КБ, не
  100–150 КБ, как обычно пишут для BLE — учитывать это в бюджете следующих
  этапов, свободного места заметно меньше, чем казалось на старте.
- Финальная сборка с реальным `secrets.ini` (без WiFi-креды, они отдельно
  через `ASTRO_WIFI_SSID`/`ASTRO_WIFI_PASS`) — тоже собралась, 63.3%.
- `flutter analyze` — чисто, `flutter test` — все 21 тест проходят,
  `flutter build apk --debug` — собирается.

## Известная мелкая недоделка

`-D CONFIG_BT_NIMBLE_MAX_CONNECTIONS=1` в `platformio.ini` конфликтует с тем
же макросом из sdkconfig платформы (компилятор пишет warning про
redefinition). Не проверяли, какое значение в итоге победило в бинарнике —
на семантику «один владелец» это не должно влиять критично (bonding и так
завязан на один сохранённый пароль на телефоне), но если важно жёстко
ограничить число одновременных подключений — перепроверить отдельно.

## Что осталось — ручная проверка на живом железе

Часы сейчас на **старой прошивке без BLE**. Телефон прошивку не заливает —
это не входило в этап (заливка только по USB или по старому WiFi-OTA
`env:ota`, оба — с компьютера через `pio`, не через приложение). Значит
первый шаг обязательно проводом.

1. Подключить часы к компьютеру по USB, из `AstroClock/`:
   `pio run -t upload` (обычный env, без WiFi — либо добавить
   `ASTRO_WIFI_SSID=... ASTRO_WIFI_PASS=...` перед командой, если нужен и
   WiFi-тумблер, не только BLE).
2. Проверить, что обычный цикл (натал, режимы, тема) не сломался.
3. В приложении: Настройки → «Часы AstroClock» → найти → подключить →
   сверить 6-значный код в системном диалоге Android с кодом на экране
   часов, подтвердить с обеих сторон.
4. Тумблер «WiFi на часах» вкл/выкл — статус на экране и в приложении
   должен меняться синхронно (через notify, в течение ~20с).
5. Перезапустить приложение — должно переподключиться к сопряжённым часам
   само, без повторного сканирования и кода.
